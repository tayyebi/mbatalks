# mbatalks.ir

کتاب آنلاین **«منابع آزمون صلاحیت حرفه‌ای مشاوران کسب و کار ۱۴۰۵»**

سایت ایستای چندصفحه‌ای فارسی (RTL) — هر مبحث یک صفحه مستقل با عنوان، توضیحات و کلیدواژه اختصاصی برای سئو.

## اجرا روی سرور

```bash
git pull
docker compose up -d      # سایت روی پورت 9237
```

همین. نه `npm`، نه `node_modules`، نه `pip`، نه nginx، نه Dockerfile — فقط ایمیج رسمی `python:3.13-alpine` و کتابخانه استاندارد پایتون. فونت‌ها هم داخل `static/fonts/` در همین مخزن هستند.

`build/serve.py` نقطه ورود کانتینر است: یک بار سایت را می‌سازد، سپس آن را سرو می‌کند و همزمان `src/`، `static/` و `build/` را زیر نظر دارد. یعنی **برای به‌روزرسانی محتوا فقط `git pull` کافی است**؛ ظرف چند ثانیه خودش دوباره می‌سازد و نیازی به ری‌استارت کانتینر نیست. `docker compose up -d` تنها بار اول لازم است (و `restart: unless-stopped` بعد از ریبوت سرور خودش بالا می‌آید).

مخزن به‌صورت read-only داخل کانتینر مانت می‌شود و خروجی در یک tmpfs (`/site`) ساخته می‌شود، پس هیچ فایلی از working tree توسط کانتینر نوشته نمی‌شود و `dist/` روی سرور اصلاً ساخته نمی‌شود.

سرور علاوه بر سرو فایل‌ها همان کارهایی را می‌کند که قبلاً `nginx.conf` انجام می‌داد: هدرهای امنیتی و CSP، فشرده‌سازی gzip، ETag و پاسخ ۳۰۴، ریدایرکت اسلش انتهایی به‌صورت نسبی، صفحه ۴۰۴ اختصاصی و کش یک‌ساله `immutable` برای دارایی‌های هش‌دار.

پورت ۹۲۳۷ پشت یک reverse proxy قرار می‌گیرد که TLS و دامنه `mbatalks.ir` را مدیریت می‌کند.

## اجرا روی سیستم خودتان

```bash
python3 build/build.py                    # فقط ساخت dist/
python3 build/serve.py --port 9237        # ساخت + سرو + بازسازی خودکار
```

## طراحی

استایل‌ها **موبایل‌اول** نوشته شده‌اند: قواعد پایه برای صفحه باریک‌اند و دو بلوک `min-width` (۷۲۰ و ۱۰۰۰ پیکسل) چیدمان‌های بزرگ‌تر را روی آن سوار می‌کنند. زیر ۷۲۰ پیکسل جستجو پشت یک دکمه جمع می‌شود و زیر ۱۰۰۰ پیکسل فهرست کتاب به کشوی کناری تبدیل می‌شود.

هیچ چیز در صفحه نباید افقی اسکرول شود؛ فقط جعبه‌های مشخص (`.table-wrap`، فرمول‌ها) داخل خودشان اسکرول می‌گیرند. `html` و `body` هم با `overflow-x: clip` سرریز اتفاقی را مهار می‌کنند.

CSP سایت `style-src 'self'` است و هیچ `style="…"` درون‌خطی اجرا نمی‌شود؛ به همین دلیل رنگ هر فصل به‌صورت کلاس `.ch-<slug>` هنگام ساخت به انتهای شیت اضافه می‌شود، نه با اتریبیوت.

### پیشرفت مطالعه

- نوار مویی زیر هدر، پیشرفت اسکرول همان صفحه را نشان می‌دهد و در انتهای متن، مبحث را خودکار «خوانده‌شده» علامت می‌زند.
- کنار عنوان هر مبحث، زمان تقریبی مطالعه (۲۰۰ کلمه در دقیقه) می‌آید.
- در فهرست کناری، یک نوار برای کل کتاب و یک نوار باریک زیر هر فصل، نسبت مباحث خوانده‌شده را نشان می‌دهد (شمارش از روی پیشوند نشانی هر فصل).
- در انتهای صفحه، اگر همچنان به پایین اسکرول کنید (overscroll)، یک نوار کوچک پر می‌شود و به مبحث بعدی می‌رود؛ پس می‌شود کتاب را بدون نشانه‌گیری روی دکمه، پشت‌سرهم خواند.
- صفحه اصلی، آخرین مبحث بازدیدشده را به‌عنوان «ادامه مطالعه» پیشنهاد می‌دهد.

همه این‌ها در `localStorage` همان مرورگر می‌مانند؛ سایت هیچ حسابی و هیچ ارسال داده‌ای ندارد.

### میان‌برهای صفحه‌کلید

| کلید | کار |
|---|---|
| `/` | رفتن به جستجو |
| `↑` `↓` `Enter` | حرکت در نتایج جستجو |
| `→` `←` | مبحث قبلی / بعدی |
| `Esc` | بستن جستجو یا کشوی فهرست |

## نوشتن محتوا

هر مبحث یک فایل HTML با یک بلوک متادیتای JSON در ابتدای آن است:

```html
<!--meta
{
  "slug": "swot",
  "title": "تحلیل SWOT",
  "description": "توضیح ۱۲۰ تا ۱۷۰ کاراکتری که همان meta description صفحه می‌شود.",
  "keywords": ["تحلیل SWOT", "ماتریس SWOT"],
  "related": ["strategy/pestel"]
}
-->
<p class="lead">…</p>
```

نام فایل با پیشوند عددی ترتیب مبحث را در فصل تعیین می‌کند (`03-swot.html`). فهرست کنار صفحه، بردکرامب، لینک‌های قبلی/بعدی، sitemap و ایندکس جستجو همگی خودکار از روی همین فایل‌ها ساخته می‌شوند.

### قواعد نگارش

| | |
|---|---|
| اعداد | در عنوان‌ها، توضیحات و متن، عدد فارسی بنویسید (`۱۴۰۵`). فونت Farsi-Digits عددهای لاتین جامانده را هم فارسی نمایش می‌دهد، ولی گوگل متن خام را ایندکس می‌کند. |
| فرمول‌ها | فقط انگلیسی؛ توضیح فارسی در `figcaption` بیاید. اسکریپت ساخت این مورد را بررسی و اخطار می‌دهد. `build/tex.py` تنها زیرمجموعه‌ای از LaTeX را می‌شناسد (`\frac`، `\sum`، `\mathrm`، `\text`، `\times`، زیرنویس و بالانویس)؛ هر دستور ناشناخته باعث شکست ساخت می‌شود، نه خروجی خراب. |
| اصطلاح انگلیسی | داخل `<span class="en">` تا جهت متن و ارقام لاتین درست بماند. |
| جدول | داخل `<div class="table-wrap">` تا در موبایل اسکرول افقی مستقل بگیرد. |

بلوک‌های محتوایی: `callout def` (تعریف)، `callout key` (نکات کلیدی)، `callout contrast` (نکته تمایز)، `callout example` (مثال)، `figure.formula` (فرمول)، `ul.vocab` (واژگان).

### صفحات مستقل

فایل‌های داخل `src/content/_pages/` به صفحه‌ای در ریشه سایت تبدیل می‌شوند (`slug` تعیین‌کننده نشانی است). این صفحات در sitemap، جستجو و لینک‌های `related` حضور دارند اما در زنجیره «قبلی/بعدی» فصل‌ها نمی‌آیند، تا ترتیب مطالعه کتاب دست‌نخورده بماند.

صفحه واژه‌نامه استثناست: جدول آن هنگام ساخت از روی `ul.vocab` همه صفحات مبحث تولید و جایگزین نشانه `<!--GLOSSARY-->` می‌شود، پس هرگز از محتوا عقب نمی‌افتد.

### بانک سؤالات

سؤالات در `src/questions.json` نگهداری می‌شوند و ساخت، از روی همان یک فایل سه خروجی می‌سازد: صفحه فهرست `/questions/`، یک صفحه برای هر فصل، و آزمون جامع `/questions/mock/`.

```json
{
  "strategy": [
    {
      "q": "متن سؤال",
      "options": ["گزینه الف", "گزینه ب", "گزینه پ", "گزینه ت"],
      "answer": 2,
      "topic": "strategy/swot",
      "why": "چرا گزینه درست، درست است",
      "wrong": "چرا سه گزینه دیگر نادرست‌اند"
    }
  ]
}
```

`answer` اندیس صفرمبناست و `topic` باید به یک صفحه مبحث موجود اشاره کند — در غیر این صورت ساخت اخطار می‌دهد. اگر در `wrong` به گزینه‌ها با حرف اشاره می‌کنید، پس از هر جابه‌جایی ترتیب گزینه‌ها آن ارجاع‌ها را هم اصلاح کنید.

توزیع سؤالات باید با وزن سرفصل‌ها در آزمون بخواند و پاسخ درست باید میان چهار موقعیت پخش باشد؛ تجمع پاسخ‌ها روی یک گزینه، آزمون را با حدس‌زدن قابل قبولی می‌کند.
